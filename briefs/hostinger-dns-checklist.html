Hostinger DNS — email setup checklist

All records go in Hostinger → hPanel → Domains → DNS / Nameservers → DNS Zone. (Not GoDaddy — your nameservers point to Hostinger.) Do these in one sitting.

1 Generate Resend's records

In Resend → Domains → Add Domain → pmrfp.com. Resend then shows you ~4–6 records with values unique to your domain. Keep that page open — you'll copy each into Hostinger in step 2.

Resend usually puts these on a send.pmrfp.com subdomain — which means they won't clash with your Hostinger inbox. Just copy them exactly as shown.

2 Paste Resend's records into Hostinger

For each row Resend shows you, click "Add Record" in Hostinger's DNS Zone and map it like this:

Resend showsHostinger: TypeHostinger: Name/HostHostinger: Value
SPF (TXT)TXTsend (the part before pmrfp.com)paste Resend's value e.g. v=spf1 include:amazonses.com ~all
DKIM (×1–3)CNAME (or TXT — match what Resend says)the host Resend gives e.g. resend._domainkeypaste Resend's value
MX (for bounces)MXsendfeedback-smtp…amazonses.com · priority 10
Copy the values verbatim from YOUR Resend page — DKIM keys are unique per domain, so I can't pre-fill them. Don't add a trailing dot, and leave TTL on Auto.

3 Add DMARC (this is the anti-spam / anti-spoof record)

This one I can give you verbatim. Add it once:

TypeName/HostValue
TXT_dmarcv=DMARC1; p=none; rua=mailto:info@pmrfp.com; fo=1
v=DMARC1; p=none; rua=mailto:info@pmrfp.com; fo=1
Start with p=none (monitor mode — safe, won't block anything). Once Resend is verified and passing for ~1 week, change p=none → p=quarantine, then later → p=reject. That's what keeps spammers from forging @pmrfp.com.

4 Do NOT touch these

RecordCurrent valueWhy keep it
MX (root)mx1.hostinger.com · mx2.hostinger.comThis is your info@pmrfp.com inbox. Deleting it = no email received.
Existing root SPF…include:_spf.mail.hostinger.com…Hostinger's inbox SPF. Resend's SPF is on the send. subdomain, so leave this one alone.
One SPF rule: you can only have ONE root TXT starting with v=spf1. Resend's goes on send. (separate), so there's no conflict. If Resend ever asks you to edit the root SPF, merge — don't add a second one.

5 Later — the website cutover (separate step)

This is the go-live move, do it after the app is deployed + smoke-tested on Vercel. Same Hostinger DNS Zone:

RecordName/HostValue (Vercel gives you the exact one)
A@ (root)Vercel's IP (remove the old Hostinger A/AAAA)
CNAMEwwwcname.vercel-dns.com
Keep email + website separate in your head: A/CNAME = website (→ Vercel). MX = email (→ Hostinger). TXT = auth (SPF/DKIM/DMARC). They all live together peacefully.
