# PMRFP Audit — 2026-05-31 (Sunday morning, fresh eyes)

Walked every major surface on pmrfp.vercel.app. Findings ranked by impact.

## 🔴 Critical (visible to first-impression visitors)

### 1. Home page TRUST band duplicates the COVERAGE grid
**Where:** `src/app/(marketing)/page.tsx` lines 198-210 (grid) + 215-223 (TRUST bullets)
**The repeat:**
- Grid: `COVERAGE Canada-first · GTA focus / FOCUS Commercial property / FOR TRADES Directory + RFP access / MEMBERSHIP $249/year`
- Bullets right below: `• Canada-first · Commercial property focused · Vendor directory · RFP visibility · Annual trade membership`
**Why bad:** Reads like the homepage repeats itself because we couldn't pick which version.
**Fix:** Kill the TRUST bullets (vanity-only); keep the grid (has the actual $249 number).
**Cost:** 5 min.

### 2. Real Estate Agents have a page but no signup lane
**Where:** `/for/real-estate` exists, H1 reads "Get properties ready, and keep them running — with vetted trades."
**The problem:** CTAs on that page are "Join as a Trade Company" + "Sign In" + "Join PMRFP." None of those are right for an REA. They want to post a quick RFP for pre-listing repairs / staging / turnovers.
**Also:** Signup only offers 4 roles: trade / supplier / property_manager / visitor. No REA option.
**Also:** The PM role bundles 3 audiences into one button: "I manage / own / build properties" — PM, owner, and builder are distinct workflows.
**Why bad:** REA lands on `/for/real-estate`, gets sold the idea, clicks CTA → bounced to a trade signup. Or they're forced to lie and pick "I manage / own / build properties."
**Fix:**
  - Add `real_estate_agent` to user roles (DB enum + types + sign-up UI + onboarding form)
  - REA onboarding skips category checkboxes (they don't service categories — they post RFPs on behalf of clients)
  - `/for/real-estate` CTAs: replace "Join as a Trade Company" with "Sign up as a Real Estate Agent" + "Post an RFP"
  - `roleHome()` maps `real_estate_agent` → `/pm-dashboard` (same dashboard as PM since the post-RFP flow is the same)
**Cost:** 45-60 min.

### 3. "12 RFPs posted · last 30 days" counter includes sample data
**Where:** `src/lib/data/stats.ts` → `rfpsPostedLast30Days` query
**The problem:** Count is technically accurate (12 RFPs created in last 30 days) but includes 5 RFPs tagged `is_demo=true`. As social proof to a first-time visitor, that's misleading optics.
**Fix:** Query should `.eq("is_demo", false)` so the public counter only reflects real activity. The number will drop to ~7-8 today, which is honest.
**Cost:** 5 min.

## 🟡 Polish / smell

### 4. "Built for every kind of commercial & residential property" — awkward phrasing
**Where:** `/for-trades` page H2.
**Reads weird:** "every kind of commercial & residential" → "every kind of property — commercial and residential" or "Commercial and residential property work, all in one place."
**Cost:** 2 min.

### 5. /for-property-managers doesn't mention REAs
Even though `/for/real-estate` exists as a vertical, the PM-facing page doesn't acknowledge agents as a fellow audience. Should at least link.
**Cost:** 5 min once the REA flow ships (#2).

### 6. Signup PM-role text bundles 3 distinct audiences
"I manage / own / build properties" → smashes Property Manager, Owner, and Builder into one button. Each has different workflows (PM = lots of RFPs, Owner = occasional, Builder = pre-construction). Currently they all get the same onboarding + dashboard.
**Fix path A (small):** Just rename role to clearer "Post RFPs for properties I manage / own / sell."
**Fix path B (proper, post-launch):** Split into 3 sub-roles with tailored onboarding.
**Cost:** A = 2 min. B = future work.

### 7. /for/real-estate CTA mismatch
**Where:** `/for/real-estate`
**Problem:** Hero CTA is "Join as a Trade Company" on a page targeting real estate agents. Direct contradiction.
**Fix:** Replaces when #2 lands.
